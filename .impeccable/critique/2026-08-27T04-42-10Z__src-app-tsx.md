## Design specificity verdict

The site feels authored for OpenFilm: the darkroom/workstation proof, local-file language, Active photograph state, and restrained sand signal are product-specific. The detector found no anti-pattern matches in `src/App.tsx` or `src/landing/Landing.tsx`.

## Overall impression

The distill pass fixed the biggest clutter problem. The landing page now has one proof frame, one four-step workflow, and one local-facts block. The workstation is substantially calmer, but it still asks the active rail to carry review, selection, filters, scan status, and Edit simultaneously.

## What's working

- The photograph now earns the largest visual region in the workstation.
- The landing page's copy is factual and shorter without losing the local-first promise.
- Progressive disclosure through Filters, More, Storage and recovery, and the Edit sheet is directionally right.

## Priority issues

1. **[P1] The active command rail still mixes primary and secondary decisions.** Pick/Reject/Clear mark, Rating, Selection, Filters, scan state, and Edit share one band. This is better than the previous layout but still exceeds the four-choice working-memory threshold. Split “review now” from “organize later”: keep Pick/Reject/Rating visible, move Selection management and scan details behind a secondary disclosure, and keep Filters/Edit visually quieter.

2. **[P1] Disabled Comparison does not explain itself to sighted first-timers.** The reason is available to assistive technology through `aria-describedby`, but the visible UI only shows a dim tab. Add a concise visible hint on hover/focus or a small status line when the user tries it.

3. **[P1] Legacy recovery can compete with the primary “Open folder” path.** `MigrationNotice` is intentionally important, but its dense paragraph and three possible actions can dominate the start surface. Keep the safety action prominent while grouping the explanation and less-common export/discard choices under the existing Storage and recovery disclosure.

4. **[P2] The More menu is a second dense workstation.** Refresh, Keyboard shortcuts, Review groups, Sort and layout, history, and backup are all siblings. Group them into “Library,” “View,” and “Recovery” sections with a tighter order.

5. **[P2] First-time guidance stops at labels.** “Review groups,” “Source,” “Analysis,” and “Resolution limited” are accurate but unexplained. Add short, local descriptions only at the relevant disclosure or empty state.

## Cognitive load

Two checklist failures remain: “one thing at a time” because the active rail exposes several independent decisions, and “minimal choices” because More and Comparison expose more than four actions. Chunking, grouping, hierarchy, working-memory support, and progressive disclosure otherwise pass.

## Persona red flags

- **Jordan, first-timer:** disabled Comparison gives no visible reason; More contains technical choices such as Review groups and Analysis; “Source” and “Resolution limited” require domain knowledge.
- **Riley, stress tester:** migration/recovery and missing-source paths are robust, but long Library names, long file paths, and many Review groups need explicit overflow and density testing.
- **Sam, accessibility-dependent:** strong semantic labels, landmarks, live regions, Escape handling, and modal focus trapping are present; visible explanations for disabled actions and full high-contrast verification remain gaps.

## Minor observations

The landing page repeats “Open the workstation” in header, hero, and closing CTA; this is acceptable for persuasion but can be reduced if the final pass still feels repetitive. Grid image menus are compact and correctly labeled for assistive technology, but sighted discoverability relies on the icon.

## Questions to carry into the finish

- Can the active rail become a focused review instrument instead of a general command center?
- Which recovery choices truly need to be visible before the first folder opens?
- Can every disabled action explain its next requirement without adding another permanent status band?
