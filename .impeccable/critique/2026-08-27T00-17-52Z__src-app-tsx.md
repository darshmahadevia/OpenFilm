## Cognitive load and emotional journey

The landing is low-to-moderate load: the hero asks users to process a headline, photograph, product proof, CTA, and browser boundary. The start path is low load for the happy path, but recovery was visually subordinate. The populated workstation was moderate load because filters, scan detail, history, Edit, View, review marks, Rating, Selection, Compare, and Clear were exposed together. The landing opens with calm authority and factual trust; the transition to an empty start screen is the main emotional valley.

## Strengths

- The real workstation screenshot is credible product proof rather than a fabricated mockup.
- The landing copy is factual about folders, supported formats, local state, and Export limits.
- Recovery intent is unusually strong: semantic status, modal focus handling, keyboard review, and recoverable Library state are present.

## Priority issues

### [P1] Too many simultaneous workstation command bands

The `workstation-toolbar` and `ActiveReviewRail` expose filters, scan detail, history, Edit, View, review marks, Rating, Selection, Compare, and Clear before the photograph. The default path should keep core review actions visible and move sort/layout and history into one secondary disclosure.

### [P1] Repeated landing proof

The same `ProofFrame` appeared in both the hero and workstation section. The second copy added page length without adding an idea. Keep one strong proof moment or make the second image materially different.

### [P1] Recovery below the primary start action

`MigrationNotice` appeared after the empty Recent Libraries area. Recovery is higher value than an empty panel and should sit immediately under the primary action.

### [P2] Mobile boundary was honest but a dead end

The mobile state offered only “Mobile access is coming soon” and a small proof image. Keep the desktop boundary explicit without implying an uncommitted roadmap, and provide the browser requirements link.

### [P2] Hidden terminology and touch sizing

Browser Library, Source, Look, and Resolution limited need concise context. Advanced controls are now disclosed, but native selects also need touch-sized targets on coarse pointers.

## Persona red flags

- **Novice:** Library, Source, Browser Library, Look, and Resolution limited require interpretation; the primary folder action is clear.
- **Power user:** shortcuts and batch actions exist but are layered under More; the active review path should stay compact.
- **Accessibility-dependent:** landmarks, focus rings, live regions, and focus containment are strong; tiny all-caps text and small native selects are risks.
- **Hardened user:** Export recovery is thoughtful; Dissolve Review group, Merge first two groups, Revert, and migration dismissal need visible consequence cues.

## Minor observations

- The local-architecture paragraph is accurate but dense; the definition list carries the clearer version.
- Repeated uppercase microcopy slows scanning at phone width.
- The empty Recent Libraries state should explain the next action.
- Moving scan detail into the toolbar is directionally correct; complete scans should read as a quiet count.

## Questions to consider

1. Should the default workstation keep only Pick, Reject, Rating, and Selection visible, or should Compare remain equally prominent?
2. Is one workstation proof moment enough for the landing page, with the workflow carrying the rest of the story?
3. Is the desktop-only boundary a permanent release constraint, or should the landing reserve space for a future mobile path?
